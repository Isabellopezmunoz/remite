Bloque 01

Fundamentos

Antes de tocar una sola tabla: por qué un email HTML no es una web normal, qué clientes lo van a renderizar y cuál es la estructura mínima que necesita.

1. Un email no es una página web

Sabes hacer una web: HTML moderno, flexbox, grid, una hoja de estilos enlazada, JavaScript. Para un email, olvida casi todo eso. Un email HTML se parece más a una web de 2003 que a una de hoy.

El motivo es simple: una web la renderiza un navegador moderno (Chrome, Firefox, Safari). Un email lo renderizan decenas de programas de correo distintos — Gmail, Outlook, Apple Mail, Yahoo, apps de móvil... — y cada uno interpreta el HTML a su manera, muchos con motores viejos y limitados.

Página web Email HTML
Layout con flexbox / grid Layout con <table> anidadas
CSS en hoja externa o <style> CSS inline, en cada etiqueta
Ancho fluido, responsive libre Ancho fijo típico de 600px
margin, position, JS... Casi solo padding en celdas, sin JS
Un navegador moderno Decenas de clientes de correo distintos
El peor caso es Outlook (Windows). Las versiones de escritorio renderizan el correo con el motor de Microsoft Word, no con un navegador. Por eso a veces hace falta código especial solo para él — lo verás más abajo.

2. Las reglas raras, una por una

Se maqueta con tablas

Flexbox y grid no son fiables en muchos clientes. La estructura — filas, columnas, el bloque centrado — se monta con <table>, <tr> y <td> anidadas. Es la técnica de hace 20 años, pero es la que funciona en todos lados. Lo verás a fondo en el Bloque 02.

El CSS va inline

Muchos clientes (Gmail entre ellos, históricamente) ignoran o eliminan los <style> y las hojas externas. La forma segura es poner el estilo en el atributo style="" de cada etiqueta:

Estilos: en una web vs. en un email

🌐 Web — el estilo vive en otro sitio:

<p class="destacado">Hola</p>

✉️ Email — el estilo viaja pegado a la etiqueta:

<p style="color:#8b76c4;font-size:16px;">Hola</p> 

<!-- ❌ Como en una web: la clase puede perderse -->
<p class="destacado">Hola</p>

<!-- ✅ En un email: el estilo va inline -->
<p style="color:#8b76c4;font-size:16px;margin:0;">Hola</p>
Más adelante: existen herramientas que escriben el CSS en un <style> normal y luego lo "inyectan" inline automáticamente (inliners). En este proyecto lo haremos a mano primero, para entender qué hace esa herramienta por dentro.

Ancho fijo de ~600px

600px es el ancho que cabe bien en el panel de lectura de la mayoría de clientes de escritorio sin cortarse. El contenido se mete en una tabla de 600px centrada; los móviles se ajustan luego con un poco de CSS responsive (Bloque 02 y 03).

Nada de JavaScript

Los clientes de correo eliminan el JavaScript por seguridad. Un email es HTML y CSS, y punto. Cualquier interacción real (un botón) es en realidad un enlace <a> que lleva a una web.

3. El doctype de un email

Una web moderna usa <!DOCTYPE html>. En email se recomienda el doctype XHTML 1.0 Transitional. No es capricho: ese doctype hace que clientes antiguos — sobre todo Outlook — rendericen las tablas de forma más predecible y respeten mejor anchos y altos.

Doctype recomendado para email

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd"> 

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN"
  "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
Ojo a la herencia XHTML: con este doctype conviene cerrar las etiquetas vacías con barra — <br />, <img ... /> — y escribir los atributos siempre entre comillas. Es buena costumbre y evita sorpresas.

4. La estructura HTML mínima

Con las reglas claras, este es el esqueleto más pequeño posible de un email: el doctype correcto, la cabecera con el charset y el viewport, y un <body> sin márgenes que contendrá las tablas. Todavía no hay layout — eso es el Bloque 02 —, solo el envoltorio.

Esqueleto mínimo de un email HTML
email.html
┌─ doctype XHTML
└─ <html>
   ├─ <head> · charset · viewport · título
   └─ <body> · sin márgenes
       └─ (aquí irán las tablas) 
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN"
  "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html lang="es" xmlns="http://www.w3.org/1999/xhtml">
<head>
  <!-- charset: imprescindible para tildes y ñ -->
  <meta charset="UTF-8" />
  <!-- viewport: que se vea bien en móvil -->
  <meta name="viewport"
        content="width=device-width, initial-scale=1.0" />
  <!-- el título no se ve en el email, pero es buena práctica -->
  <title>Asunto del email</title>
</head>
<!-- body sin margen ni padding: las tablas controlan el espacio -->
<body style="margin:0; padding:0;">

  <!-- Aquí dentro irán las tablas (Bloque 02) -->

</body>
</html>

Qué hace cada pieza

  • El doctype — fuerza el modo de renderizado predecible para tablas, sobre todo en Outlook.
  • <meta charset="UTF-8"> — sin esto, las tildes, las ñ y los símbolos salen como caracteres rotos.
  • <meta name="viewport"> — le dice al móvil que use su ancho real, no que finja ser un escritorio.
  • style="margin:0; padding:0;" en el body — quita el margen que algunos clientes ponen por defecto; el espaciado lo controlan las tablas.
Recapitulando: un email es HTML antiguo a propósito — tablas, CSS inline, 600px de ancho, sin JS — porque tiene que sobrevivir a decenas de clientes de correo, y Outlook lo renderiza con Word. En el Bloque 02 empezamos a montar la estructura real con tablas anidadas.
